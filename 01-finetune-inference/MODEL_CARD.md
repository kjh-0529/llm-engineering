# Qwen3-1.7B Korean Technical Q&A (QLoRA adapter)

A LoRA adapter for [Qwen/Qwen3-1.7B](https://huggingface.co/Qwen/Qwen3-1.7B) that answers Korean technical and programming questions more consistently in Korean and closer to the reference style. Trained on a single Tesla T4. Code, data processing and the full evaluation: [github.com/kjh-0529/llm-engineering](https://github.com/kjh-0529/llm-engineering/tree/main/01-finetune-inference).

**Read the limitations below before use: it does not know HPC tools such as Slurm, and it invents details confidently.**

## Results

Greedy decoding, the same Korean system prompt for both models.

| Technical test set (200 questions) | Base | This adapter |
|---|---|---|
| Korean answers (of 178 with a Korean reference) | 84.8% | **93.3%** |
| chrF vs. reference | 22.2 | **27.9** |
| Code blocks intact (of 65) | 76.9% | **81.5%** |
| Mean answer length | 302 chars | 404 chars |

| HPC set (30 questions on Slurm, MPI, CUDA, ...) | Base | This adapter |
|---|---|---|
| Korean answers | 100% | 100% |
| chrF vs. reference | 18.2 | **12.9** (worse) |
| Mean answer length | 360 chars | 614 chars |

## Limitations

- **Wrong HPC facts.** Both the base model and this adapter invent Slurm commands (e.g. `scontrol cancel` instead of `scancel`). Fine-tuning made such answers longer and more detailed, not more correct.
- **Verbose, sometimes repetitive.** The training answers are long explanations, so answers grew by about a third; some repeat a sentence.
- **Training data provenance.** KULLM-v2 is a DeepL translation of Alpaca and Dolly; part of the original English data was generated by GPT models. Code that the translator itself had turned into Korean was filtered out, but the filter is a heuristic.
- Evaluated with automatic metrics and a small sample of answers read by hand; no human preference study.

## Usage

```python
from peft import PeftModel
from transformers import AutoModelForCausalLM, AutoTokenizer

adapter = "kjh0529/qwen3-1.7b-ko-tech-qlora"
base = AutoModelForCausalLM.from_pretrained("Qwen/Qwen3-1.7B", dtype="auto", device_map="auto")
model = PeftModel.from_pretrained(base, adapter)
tok = AutoTokenizer.from_pretrained(adapter)

messages = [
    {"role": "system", "content": "당신은 정확하고 간결하게 한국어로 답하는 기술 도우미입니다."},
    {"role": "user", "content": "파이썬에서 리스트를 정렬하는 방법은?"},
]
inputs = tok.apply_chat_template(messages, add_generation_prompt=True, enable_thinking=False,
                                 return_tensors="pt", return_dict=True).to(model.device)
out = model.generate(**inputs, max_new_tokens=512)
print(tok.decode(out[0][inputs["input_ids"].shape[1]:], skip_special_tokens=True))
```

## Training

- **Data:** 3,716 examples from [nlpai-lab/kullm-v2](https://huggingface.co/datasets/nlpai-lab/kullm-v2) (Apache-2.0): 2,716 technical (Alpaca and Dolly parts, filtered for broken or translated code) and 1,000 general.
- **Method:** QLoRA. 4-bit NF4 base with double quantization, float16 compute (no bfloat16 on the T4), LoRA r=16, alpha=32, dropout 0.05 on all attention and MLP projections; loss on answer tokens only.
- **Schedule:** 2 epochs, 16 sequences per update (2 x 8 accumulation), max 1,024 tokens, learning rate 2e-4 cosine, 3% warm-up, paged 8-bit AdamW. 1 h 26 min on one Tesla T4.
- **Loss:** validation 2.057 (step 100) → 2.003 (step 200) → 2.001 (step 234).
